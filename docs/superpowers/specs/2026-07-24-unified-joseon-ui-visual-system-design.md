# 통합 조선 민속 판타지 UI·전투 비주얼 설계

작성일: 2026-07-24
상태: 사용자 승인
범위: 기존 기능의 시각 통합과 모바일 레이아웃 개선

## 1. 목표

로비, 캐릭터·스테이지 선택, 도감, 기록, 수련 진입, 전투 HUD, 레벨업, 일시정지, 결과 화면을 하나의 조선 민속 판타지 모바일 게임처럼 보이게 한다. 새 캐릭터·무기·스테이지나 새 밸런스 시스템은 추가하지 않는다.

작업은 두 단계로 진행한다.

1. 공통 UI 시스템과 비전투 화면 이관
2. 전투 타일·HUD·overlay 이관

전체 테스트와 웹 빌드는 두 단계가 모두 끝난 뒤 한 번만 수행한다.

## 2. 시각 언어

- 기본 배경: 짙은 남색
- 본문 표면: 따뜻한 아이보리
- 주요 강조: 금색
- 위험·선택 경고: 제한된 적색
- 성공·해금·특수 상태: 제한된 청록색
- 장식: 옻칠, 목재, 금속 질감은 테두리와 모서리에서만 사용
- 문양: 화면 전체 배경이 아니라 작은 모서리·분할선·아이콘에만 사용
- 제목: 기존 조선풍 제목 서체
- 본문·숫자: 작은 모바일 화면에서 읽기 쉬운 본문 서체

기본 능력치는 정수로 표시한다.

- 체력 `105`
- 공격력 `20`
- 이동속도 `125`

치명타율, 피해 감소율, 증가율처럼 본질적으로 비율인 값만 `%`를 사용한다. 공격력 배율을 `100%`로 표시하지 않는다.

## 3. 공통 UI 아키텍처

### 3.1 테마 토큰

`JoseonUiTheme`를 확장해 색상, 글꼴, 간격, 모서리, 선 두께, 그림자, SafeArea 행동 영역 높이를 관리한다. 화면 파일에서 같은 의미의 색상과 테두리를 직접 하드코딩하지 않는다.

### 3.2 공통 컴포넌트

- `JoseonScaffold`: 배경, 실제 MediaQuery inset, 상단 바, Expanded 본문, 고정 하단 영역
- `JoseonTopBar`: 뒤로가기, 제목, 선택적 자원·설정 행동
- `JoseonPanel`: 남색 또는 아이보리 표면과 공통 테두리
- `JoseonPrimaryButton`: 출진·선택 완료 같은 주 행동
- `JoseonSecondaryButton`: 취소·보조 이동
- `JoseonResourceChip`: 엽전·혼옥·유료 재화
- `JoseonTabBar`: 인물·무기·증강과 도감 분류
- `JoseonSelectionCard`: 캐릭터·스테이지 선택 상태와 잠금 상태
- `JoseonCodexCard`: 해금·잠금 도감 항목
- `WeaponStarRating`: 1~6레벨의 유일한 표시 규칙

각 컴포넌트는 데이터나 게임 로직을 소유하지 않는다. 화면이 기존 모델 값을 전달하고 컴포넌트는 표시와 입력만 담당한다.

## 4. 반응형 레이아웃

지원 검증 크기는 390×844, 375×667, 430×932다.

- 고정 844px 높이를 사용하지 않는다.
- `SafeArea`와 `MediaQuery.viewPadding`을 실제 기기 inset의 기준으로 사용한다.
- 상단과 하단 고정 영역을 제외한 본문은 `Expanded`가 차지한다.
- 콘텐츠가 넘칠 때 본문만 스크롤한다.
- 하단 탭과 선택 완료 버튼은 스크롤 컨텐츠에 포함하지 않는다.
- 선택 완료·출진 버튼은 하단 홈 인디케이터 바로 위에서 항상 보여야 한다.
- `LayoutBuilder`로 compact·regular 폭을 구분하며 세로 모바일을 기본으로 한다.
- 글자 크기 축소로 문제를 숨기지 않고 카드 폭, 행 수, 정보 우선순위를 조정한다.

## 5. 1단계: 비전투 화면

### 5.1 로비

기존 관아 배경과 캐릭터 이미지를 유지한다. 상·하단 그라데이션으로 텍스트와 버튼 가독성을 확보한다. 자원은 하나의 정돈된 프레임으로 묶고 설정 버튼과 동일한 선 두께를 사용한다.

캐릭터 아래의 큰 녹색 원은 제거하고 금빛·청록색의 낮은 타원형 발판, 접지 그림자, 약한 발광으로 교체한다. 캐릭터는 원본 비율과 적절한 필터 품질을 유지한다.

정보 우선순위는 `오늘의 출진` → 스테이지명 → 최고 기록 → 캐릭터 → 출진 버튼이다. 하단 독은 고정하고 버튼의 프레임·아이콘·선 두께를 통일한다.

수련은 계정 공통 시스템이므로 캐릭터 카드 내부에 두지 않는다. 로비 또는 하단 메뉴에 독립 진입점을 둔다.

### 5.2 캐릭터 선택

모바일에서는 중앙 캐릭터 한 명을 크게 보는 `PageView` 캐러셀을 사용한다. 양옆 카드 일부를 노출해 이동 가능성을 전달한다.

카드는 다음을 포함한다.

- 실제 캐릭터 전신 이미지
- 이름 한 줄
- 역할 태그
- 체력·공격력·이동속도 정수
- 시작 무기
- 고유 능력 이름
- 고유 능력 설명 최대 두 줄
- 선택·잠금 상태와 해금 조건

선택 상태는 금색 테두리, 체크, 약한 발광, 강조된 이름 중 최소 두 가지로 표현한다. 깨진 문자열과 말줄임으로 이름이 훼손되는 상태를 허용하지 않는다.

### 5.3 스테이지 선택

세로 모바일에서는 한 장씩 넘기는 대형 가로 비율 카드 또는 PageView를 사용한다. 각 카드에 스테이지 삽화, 이름, 두 줄 설명, 난이도, 생존 목표, 보스 등장 시점, 최고 기록, 주요 보상, 잠금·클리어 상태를 통합한다.

카드와 상세 패널, 완료 버튼이 서로 떨어진 별도 UI처럼 보이지 않게 한다. 완료 버튼은 고정 하단 행동 영역에 둔다.

### 5.4 도감

인물·무기·증강 탭을 공통 `JoseonTabBar`로 제공한다. 모바일에서 한 화면에 최소 4개 항목을 식별할 수 있는 밀도를 유지한다.

해금 항목은 실제 이미지, 이름, 역할, 핵심 효과를 표시한다. 잠금 항목은 실루엣, 자물쇠, 해금 조건만 표시하고 원본 이미지를 노출하지 않는다.

### 5.5 기록

상단 요약은 2열의 낮은 카드로 유지하되 숫자를 크게, 항목 이름을 작은 보조 텍스트로 표시한다. 캐릭터 기록은 초상과 함께 조밀한 행 목록으로, 무기 기록은 아이콘·사용 횟수·누적 처치·누적 피해·최고 등급을 포함한 목록으로 구성한다.

### 5.6 수련

기존 `TrainingProgress`와 저장 데이터를 읽는 표시 화면 및 로비 진입점까지만 만든다. 엽전 구매, 능력치 계산, 다음 출진 적용 로직이 이미 존재할 때만 연결한다. 존재하지 않는 계산식이나 경제 밸런스는 새로 만들지 않고 현재 미구현 상태를 명확히 표시한다.

## 6. 2단계: 전투 화면

### 6.1 기본 타일과 decal

기본 돌바닥은 4~6개, 흙바닥은 3~4개의 저대비 변형을 사용한다. 돌·흙 연결, 가장자리, 균열, 이끼 변형을 별도로 둔다.

웅덩이, 나무뿌리, 핏자국, 잡초, 부적 조각, 수레 흔적 등 큰 특징은 기본 타일에서 분리된 decal이다. 고정 시드로 위치, 회전, 좌우 반전을 다양화한다.

중앙 전투 공간 60%는 단순하게 유지하고 decal은 가장자리, 랜드마크, 경계 주변에 집중한다. 경험치 구슬과 공격 예고보다 배경 대비를 낮춘다.

청크·배치 구조는 유지한다. 타일 좌표의 정수 정렬, sampling, atlas padding 또는 extrude를 점검해 1px 이음새와 texture bleeding을 제거한다.

### 6.2 HUD

시간, 레벨, 경험치, 처치 수, 무기 슬롯만 상시 표시한다. 처치 수에는 의미가 분명한 작은 아이콘을 붙인다. 외곽선과 장식을 얇게 하고 전투 공간을 가리는 높이를 늘리지 않는다.

조이스틱은 입력하지 않을 때 투명도를 낮춘다. HUD와 조이스틱은 카메라와 독립된 화면 overlay로 유지한다.

### 6.3 WeaponStarRating

- 1레벨: 채운 별 1 + 빈 별 4
- 2레벨: 채운 별 2 + 빈 별 3
- 3레벨: 채운 별 3 + 빈 별 2
- 4레벨: 채운 별 4 + 빈 별 1
- 5레벨: 채운 별 5
- 6레벨: 청록 또는 파란 별 5 + `통달`

6레벨을 별 6개로 표시하지 않는다. 작은 HUD에서는 빈 별을 생략할 수 있지만 6레벨의 통달 표식은 반드시 유지한다.

적용 범위는 레벨업 카드, 인게임 무기 슬롯, 일시정지 빌드, 결과, 무기 도감, 상세 정보, 개발 갤러리다.

### 6.4 전투 overlay

레벨업, 일시정지, 런 종료 화면도 공통 패널·버튼·별 등급을 사용한다. 기존 선택, 재개, 종료, 저장, 동기화 흐름은 변경하지 않는다.

## 7. 데이터 흐름

1. 화면은 기존 `LobbyController`, 콘텐츠 정의, 저장 상태, 런 결과에서 데이터를 읽는다.
2. 화면 모델 또는 작은 presentation adapter가 정수 능력치, 잠금 문구, 별 등급을 생성한다.
3. 공통 컴포넌트는 값을 렌더링하고 사용자 입력을 기존 callback으로 반환한다.
4. 기존 controller가 선택 저장, 게임 시작, 진행 동기화를 수행한다.

UI는 게임 밸런스 값을 다시 계산하거나 별도의 복제 상태를 만들지 않는다.

## 8. 에셋 오류 처리

- 기존 에셋을 우선 사용한다.
- 서로 다른 항목이 같은 임시 이미지나 atlas 전체를 공유하면 `docs/UI_ASSET_GAPS.md`에 기록한다.
- 개발 빌드에서 누락 항목은 `ASSET MISSING`과 키를 표시한다.
- 잠금 항목은 실제 이미지를 숨기고 실루엣과 조건만 보인다.
- 이미지 없는 카드를 Material 아이콘만으로 최종 완료 처리하지 않는다.
- 이미지 로드 실패가 선택·뒤로가기·출진 같은 기능 흐름을 막지 않게 한다.

## 9. 테스트

기능 묶음별로 다음을 검증한다.

- 공통 Scaffold가 실제 SafeArea와 고정 하단 영역을 지킨다.
- 390×844, 375×667, 430×932에서 overflow와 버튼 잘림이 없다.
- 선택 화면에서 잠금 항목을 확정할 수 없다.
- 캐릭터 능력치가 정수로 표시되고 공격력 100% 문구가 없다.
- 수련 진입이 기존 저장 데이터를 초기화하지 않는다.
- 잠금 도감 항목에 원본 이미지가 노출되지 않는다.
- 1~6레벨 별 등급 규칙이 모든 대상 화면에서 동일하다.
- 전투 HUD와 조이스틱이 카메라 이동과 독립적이다.
- 고정 시드에서 타일 배치가 재현되고 이음새가 보이지 않는다.
- 장식 밀도가 중앙 전투 가독성을 침범하지 않는다.

작업 중에는 변경 파일 관련 테스트와 필요한 `flutter analyze`, Chrome hot reload, 세 가지 모바일 크기 확인만 수행한다.

모든 작업 마지막에만 다음을 각각 한 번 실행한다.

1. `flutter analyze`
2. 전체 `flutter test`
3. `flutter build web`

Android와 iOS 빌드는 별도 요청 전까지 실행하지 않는다. 새 외부 터널은 명시적 요청이 있을 때만 연다.

## 10. 범위 제외

- 새 캐릭터·무기·스테이지
- 전투 밸런스와 스폰 변경
- 기존 저장 데이터 초기화
- 새로운 수련 경제·능력치 계산식
- 상용 게임 UI의 직접 복제
- 기존 로비 배경 폐기
