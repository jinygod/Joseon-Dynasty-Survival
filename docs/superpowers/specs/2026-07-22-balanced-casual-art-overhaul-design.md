# 균형형 캐주얼 전투 화면·대표 아트 교체 설계

## 1. 목적

현재 전투 화면은 플레이어와 방어 표시가 지나치게 크고, 어두운 배경 위에 HUD·사거리 원·경고선·피해 숫자가 겹쳐 모바일에서 전투가 복잡하게 보인다. 이번 작업은 특정 상용 게임의 캐릭터나 UI를 복제하지 않고, 모바일 생존 액션 장르의 즉시 읽히는 비율과 후반 대량 처치 감각을 조선 민속 판타지로 재구성한다.

최종 목표는 플레이어 3종과 적 13종 전체의 아트 교체다. 첫 제작 범위는 스타일 기준이 될 대표 세트로 제한한다. 대표 세트가 실제 전투에서 품질 기준을 통과한 뒤 동일 규격으로 나머지 아트를 확장한다.

## 2. 승인된 방향

- 화면 구성: 균형형 캐주얼
- 렌더 스타일: 3~4등신, 굵고 깨끗한 외곽선, 2~3단 셀 셰이딩
- 문화적 어휘: 조선 철릭·두루마기·갓·망건·부적·장승·삿갓·환도와 한국 민속 요소
- 금지: 특정 게임의 캐릭터, UI 배치, 아이콘, 이펙트 형태 또는 색 배합의 직접 복제
- 목표 화면: 밝은 저대비 전장 위에 작지만 명확한 캐릭터와 높은 적 밀도, 굵고 선명한 공격 이펙트

## 3. 대표 세트

### 3.1 플레이어

기존 `exorcist_dosa` ID와 저장 호환성을 유지하고 외형을 **퇴마 검객**으로 교체한다. 철릭과 짧은 두루마기, 작은 갓 또는 망건, 큰 환도, 허리의 부적 묶음을 사용한다. 환도와 부적을 동시에 보유해도 장비가 자연스럽게 보이는 디자인으로 만든다.

실루엣 우선순위는 큰 환도, 넓은 소매, 갓·망건의 머리 윤곽, 주홍색 허리 부적 순서다. 얼굴은 게임 크기에서도 눈과 입의 방향이 읽히는 단순한 표정으로 구성한다.

### 3.2 적 4종

| 역할 | ID | 디자인 핵심 | 전투 판독 요소 |
| --- | --- | --- | --- |
| 무리형 | `plague_rat_swarm` | 누더기 천과 녹빛 눈을 가진 3마리 쥐 묶음 | 낮고 넓은 실루엣, 빠른 발 움직임 |
| 돌진형 | `vengeful_spirit` | 찢어진 한복과 끊긴 하반신의 원혼 | 길게 흐르는 머리·소매, 돌진 전 몸을 접는 자세 |
| 원거리형 | `sakkat_specter` | 넓은 삿갓과 좁은 망령 몸체 | 삿갓의 수평선, 발사 전 부적불을 모으는 손 |
| 방어형 | `dokkaebi` | 짧은 뿔, 큰 코, 조선식 조끼와 방망이 | 넓은 어깨, 낮은 중심, 정면 방패 호 |

## 4. 스프라이트·애니메이션 계약

대표 플레이어와 적 4종은 모두 투명 RGBA PNG의 4×4 아틀라스를 사용한다. 한 프레임은 128×128이며 아틀라스는 512×512다. 공통 인덱스는 다음과 같다.

- 0~3: 이동 4프레임
- 4~7: 공격 4프레임
- 8~9: 피격 2프레임
- 10~15: 사망 6프레임

플레이어의 정지는 이동 첫 프레임과 작은 코드 기반 호흡 움직임을 사용한다. 공격 중에는 4~7번 프레임을 사용하고, 환도 또는 부적의 실제 공격 방향에 맞춰 좌우 반전한다. 적도 실제 행동 상태와 아틀라스 상태를 연결하며, 공격 예고 단계에서는 공격 첫 프레임을 유지해 준비 동작을 보여준다.

모든 프레임은 같은 발 기준점, 머리 높이, 장비 크기와 빛 방향을 유지한다. 외곽선은 소스 해상도에서 5~7픽셀을 기준으로 하며 반투명 가장자리, 사진 질감, 작은 픽셀 노이즈를 사용하지 않는다.

## 5. 화면 비율과 카메라

기준 기기는 390×844 CSS 픽셀의 세로 화면이다. 게임 월드는 기기 크기에 맞춰 보이되 캐릭터의 화면 점유율은 다음 범위로 고정한다.

- 플레이어 시각 크기: 56
- 쥐떼: 32
- 원혼·삿갓 망령: 40
- 도깨비: 44
- 일반 적 충돌 크기: 기존 18 유지
- 플레이어 충돌 크기: 기존 24 유지

시각 크기와 충돌 크기를 분리해 캐릭터는 읽히되 밀집 전투의 충돌 비용과 이동 감각은 바꾸지 않는다. 적별 시각 크기 카탈로그를 도입하고 `EnemyRank` 하나로 모든 일반 적 크기를 강제하지 않는다.

후반 목표는 화면 평균 30~55마리, 순간 최대 60마리 안팎이다. 기존 전역 상한 96과 프레임당 생성 상한은 유지한다. 적 수를 늘리기 위해 체력을 올리지 않으며, 대표 세트에서는 현재 웨이브 밸런스를 보존하고 시각 크기·겹침·효과 예산을 먼저 조정한다.

## 6. 배경과 색상

검은 단색 배경을 밝은 조선 마을 전장으로 교체한다. 첫 스테이지는 한지빛 흙길, 흐린 옥색 풀, 낮은 채도의 기와·돌·목재 흔적을 사용하는 반복 가능한 배경 타일 또는 저비용 절차 렌더로 구성한다. 배경에는 캐릭터 외곽선과 비슷한 진한 테두리를 사용하지 않는다.

기본 팔레트는 다음 역할로 구분한다.

- 배경: 한지 베이지, 회옥색, 흐린 흙갈색
- 플레이어: 주홍, 남색, 황동, 따뜻한 피부색
- 일반 적: 역할별 녹색·청회색·자주색·주황갈색
- 적 공격 경고: 채도가 낮은 진홍색, 최대 불투명도 0.32
- 플레이어 공격: 배경과 겹치지 않는 청백·금색·주홍·오방색

## 7. HUD와 조작 화면

현재 큰 테두리 상태 패널을 얇은 상단 HUD로 교체한다.

- 좌측: 48픽셀 터치 영역의 일시정지 버튼
- 중앙: 가장 큰 숫자로 남은 시간 또는 경과 시간
- 우측: 레벨과 처치 수를 작은 아이콘·숫자로 표시
- 상단 두 번째 줄: 체력 바와 경험치 바
- 무기 정보: 화면 우측 상단에 작은 아이콘 슬롯으로 표시하고, 상세 이름 목록은 일시정지 화면으로 이동
- 연속 처치: 중앙 상단에 짧게 나타난 뒤 사라짐
- 조이스틱: 104 크기, 평상시 불투명도 0.35, 조작 중 0.55

HUD는 SafeArea를 존중하고 전투 월드를 가리는 면적을 세로 화면의 12% 이하로 제한한다. 모든 터치 대상은 최소 48×48을 유지한다.

## 8. 무기와 공격 표현

공격 이펙트의 모양, 판정 방향, 범위와 타이밍은 기존 `AttackSpec`과 `AttackGeometry`에서 파생한다. 아트 컴포넌트가 별도의 피해 범위를 소유하지 않는다.

### 8.1 환도

- 기본: 청백색 칼날 중심선과 얇은 한지 흰색 잔상
- 강타: 외곽 금색, 중심 청백색, 20ms 히트스톱
- 검기: 진행 방향이 분명한 초승달 형태, 꼬리는 빠르게 사라짐
- 마스터: 첫 베기는 전방 반원, 중간 베기는 점차 커지는 원호, 마무리는 금색 테두리와 청백색 중심의 환도 폭풍
- 마스터 시작과 마무리만 35ms 히트스톱과 제한된 화면 흔들림 적용

### 8.2 부적

- 비행 부적: 주홍 인장과 황색 종이, 방향에 맞춰 회전
- 부착: 적 몸 위가 아니라 발밑 또는 머리 위의 작은 인장으로 표시
- 폭발: 주홍 중심, 황금 테두리, 짧은 먹선 파편
- 오방색 결계: 청·백·적·흑·황을 단순한 다섯 구획으로 사용하고 내부는 투명하게 유지
- 마스터 결계는 생성 시 한 번만 강한 피드백을 내고 연속 폭발마다 화면을 흔들지 않음

### 8.3 봉마참

환도의 청백 궤적이 부적의 주홍 인장을 가르면 금빛 균열이 생긴다. 폭발은 주홍·금색 중심과 청백색 외곽 고리로 구성한다. 첫 발동에만 이름과 짧은 효과음을 표시하고 이후에는 재사용 대기시간 동안 UI를 반복 노출하지 않는다.

## 9. 적 경고와 가독성

- 돌진형: 몸을 접는 0.45초 준비 자세와 얇은 진홍 방향 띠
- 원거리형: 손에 모이는 부적불과 작은 목표 지점 표시
- 방어형: 거대한 주황 사각형을 제거하고 적 전방 90도에 낮은 방패 호를 표시
- 무리형: 별도 위험선을 사용하지 않고 속도와 군집 움직임으로 역할을 전달

동시에 표시하는 전체 화면 공격 경고의 불투명도 합계를 제한한다. 플레이어 이펙트 아래에서도 적 공격 경고가 보이도록 렌더 우선순위를 유지하며, 같은 유형의 경고가 겹치면 가장 가까운 것만 선명하게 표시한다.

## 10. 피해 숫자와 사망 연출

일반 피해 숫자는 작고 빠르게 사라지며 같은 적의 짧은 시간 피해를 합산한다. 치명타·방어 파괴·마스터 공격만 크기와 색을 올린다. 화면 중앙의 피해 숫자 총량은 기존 성능 예산 24개를 넘지 않는다.

사망은 각 적의 6프레임 애니메이션과 역할별 짧은 분해 효과를 사용한다. 쥐떼는 흩어짐, 원혼은 청회색 종이·연기 조각, 삿갓 망령은 삿갓 낙하와 영체 소멸, 도깨비는 방망이를 놓치고 뒤로 넘어지는 동작을 사용한다. 피와 고어는 사용하지 않는다.

## 11. 아트 생산과 검수 순서

1. 퇴마 검객 단일 정지 포즈 제작 및 실루엣 검수
2. 퇴마 검객 4×4 아틀라스 제작·게임 연결
3. 적 4종 정지 포즈를 한 장의 라인업으로 제작해 크기·팔레트 검수
4. 적별 4×4 아틀라스 제작·게임 연결
5. 밝은 전장 배경과 축소 HUD 연결
6. 환도·부적·봉마참 이펙트 교체
7. 390×844 실제 전투 골든과 웹·Android 실기 검수
8. 대표 세트가 기준을 통과한 뒤 나머지 플레이어 2종과 적 9종을 같은 계약으로 확장

정지 포즈와 아틀라스는 프로젝트 전용 원본으로 제작하고 소스 프롬프트·생성일·권리 상태를 `asset-rights-ledger.csv`에 기록한다. 승인 전 에셋은 `temporary`, 대표 전투 골든과 실기 검수를 통과한 에셋만 `approved`로 전환한다.

## 12. 구조와 데이터 흐름

- `AssetCatalog`: 안정적인 콘텐츠 ID에서 새 런타임 경로로 매핑
- `SpriteAtlasContract`: 128 프레임 크기, 4×4 배열, RGBA와 승인 상태 검증
- `ActorVisualSpec`: 콘텐츠 ID별 시각 크기·발 기준점·그림자 크기 정의
- `PlayerComponent`·`EnemyComponent`: 게임 상태를 공통 애니메이션 상태로 변환
- `AttackSpec`·`AttackGeometry`: 피해와 이펙트가 공유하는 단일 방향·범위 데이터 제공
- 프레젠테이션 컴포넌트: 데이터에서 궤적·색·수명만 렌더하고 피해 판정은 소유하지 않음

에셋 로드 실패 시 게임을 중단하지 않고 역할별 굵은 외곽선 대체 실루엣으로 폴백한다. 누락·크기 오류·알파 오류는 진단 로그와 테스트 실패로 기록한다.

## 13. 테스트와 완료 기준

### 자동 테스트

- 5개 대표 아틀라스의 512×512 RGBA·4×4 계약
- 모든 상태의 프레임 인덱스와 비루프 공격·사망 애니메이션
- 콘텐츠 ID별 시각 크기와 기존 충돌 크기 보존
- 환도·부적·봉마참 판정과 렌더 방향·범위 일치
- HUD SafeArea, 48×48 터치 영역, 390×844 및 큰 글자 배율 레이아웃
- 390×844 초반·중반·후반·레벨업 화면 골든
- 고정 시드 5분 런의 적·투사체·피해 숫자·이펙트 예산
- Flutter analyze, 전체 테스트, 웹 빌드, Android 디버그 빌드

### 실제 플레이 체크

- 플레이어와 적 4종을 실루엣만 보고 구분 가능
- 적 30~55마리 상황에서도 플레이어 위치와 위험 경고가 보임
- 환도 레벨 1과 마스터가 즉시 다른 공격으로 보임
- 부적 부착·폭발·결계의 순서가 한눈에 읽힘
- 봉마참을 일반 환도·부적 공격과 색과 소리로 구분 가능
- 방어형의 정면과 측후면 차이를 설명 없이 이해 가능
- 5분 후반 구간에서 지속적인 흰 화면·과도한 흔들림·숫자 벽이 없음
- 실제 Android 기기에서 후반 프레임 저하와 터치 방해가 허용 범위 내임

대표 세트 완료는 자동 테스트 통과만으로 선언하지 않는다. 실제 모바일 화면 캡처와 플레이 체크 결과를 함께 기록하며, 재미와 캐릭터 매력은 관찰자가 직접 평가한다.

## 14. 범위 밖

- 나머지 플레이어 2종과 적 9종의 실제 제작은 대표 세트 승인 이후 단계
- 새로운 상점, 과금, 메타 성장, 스테이지 규칙 추가
