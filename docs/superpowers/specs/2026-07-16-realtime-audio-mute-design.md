# 실시간 오디오 음소거 설계

## 목표

음악 또는 효과음 음량을 0%로 바꾸는 즉시 해당 채널의 재생 중인 음성과 대기 중인 재생 요청을 모두 차단한다. 음량을 다시 올려도 음소거로 중단된 오래된 음성은 자동으로 되살리지 않는다.

## 확인된 원인

`GameAudioService.play`는 재생 요청이 들어오는 순간의 설정만 읽는다. 설정 화면에서 음량이 0%가 되어도 이미 생성된 `AudioPlaybackHandle`은 중단되지 않고, 직렬 대기열에 들어간 요청은 이전 음량으로 나중에 재생될 수 있다. `AudioSettingsController`의 변경 알림도 현재 `GameAudioService`에 전달되지 않는다.

## 구조

- `GameAudioService.applySettings()`는 최신 설정을 읽어 음량이 0%인 채널의 활성 음성을 서비스 대기열에서 중단한다.
- 재생 요청은 대기열에 들어가기 전뿐 아니라 실제 백엔드를 호출하기 직전에도 최신 설정을 다시 확인한다.
- `PixelSurvivorApp`은 `AudioSettingsController` 변경을 듣고 `applySettings()`를 호출한다. 저장된 0% 설정을 불러오는 경우에도 같은 경로를 사용한다.
- 음악 0%는 음악 채널만, 효과음 0%는 효과음과 UI 채널만 중단한다.
- 음량을 다시 올리는 동작은 중단된 핸들을 재개하거나 이전 큐를 재생하지 않는다. 이후 발생하는 정상적인 장면 음악 또는 효과음 요청만 새 음량으로 재생한다.
- 음성 중단 실패는 기존 `AudioDiagnostic` 경로로 보고하고 다른 음성 정리를 계속한다.

## 테스트

- 재생 중인 음악을 0%로 변경한 뒤 `applySettings()`를 호출하면 음악 핸들이 중단된다.
- 재생 중인 효과음과 UI 음성을 0%로 변경하면 둘 다 중단되고 음악은 유지된다.
- 음소거 직전에 대기열에 들어간 요청은 백엔드 재생까지 도달하지 않는다.
- 앱 설정 컨트롤러 알림이 오디오 서비스 동기화를 호출하고, 앱 종료 시 리스너를 제거한다.

## 제외 범위

0%가 아닌 음량 변경 중 이미 재생 중인 음성의 볼륨을 실시간으로 조절하는 기능과 햅틱 피드백은 이번 수정에 포함하지 않는다.
