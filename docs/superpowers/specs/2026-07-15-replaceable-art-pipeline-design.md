# 교체 가능한 이미지 에셋 파이프라인 설계

## 목표

최종 이미지 제작을 뒤로 미루고도 게임 기능 개발을 계속한다. 현재 캐릭터, 몬스터, 효과, 배경 이미지는 임시 자산으로 취급하며, 이후 확정할 **아기자기하고 귀여운 조선 민속풍** 이미지로 게임 로직 수정 없이 교체할 수 있게 한다.

여기서 아틀라스는 여러 애니메이션 프레임을 같은 크기의 칸으로 나누어 한 PNG에 모은 이미지다. 런타임은 이미지 내용이 아니라 파일 경로, 칸 크기, 행·열 수만 사용한다.

## 범위

이번 작업은 최종 이미지를 새로 만들거나 기존 이미지를 승인하지 않는다. 다음 기반 작업만 수행한다.

- 자산 종류별 파일 경로와 아틀라스 칸 규격을 코드의 단일 계약으로 관리한다.
- 같은 경로와 규격을 지킨 PNG는 파일 교체만으로 반영되게 한다.
- 해상도, RGBA 형식, 투명 배경, 프레임 개수를 자동 검증한다.
- 파일 누락이나 로딩 실패가 게임 시작과 전투 진행을 막지 않게 안전한 임시 표시를 사용한다.
- 자산의 상태를 `temporary` 또는 `approved`로 구분한다.
- 최종 자산은 사용자 검토 후에만 `approved`로 바꾸고 권리·출처 장부에 기록한다.

런타임 중 스킨 다운로드, 원격 자산 교체, 사용자 모드 지원은 1.0 범위에서 제외한다. 여기서 “언제든 교체”는 개발 중 같은 계약의 로컬 파일을 바꿔 다음 빌드에 반영한다는 뜻이다.

## 구조

`AssetCatalog`는 논리 자산 ID와 런타임 파일 경로를 연결한다. 별도 `SpriteAtlasContract`는 자산마다 다음 값을 가진다.

- 논리 ID
- 런타임 경로
- 한 프레임의 너비와 높이
- 열 수와 행 수
- 투명 배경 필요 여부
- 현재 상태: `temporary` 또는 `approved`

캐릭터·몬스터·보스·무기 효과·전투 효과·스테이지 장식은 이 계약으로 검증한다. 스테이지 바닥처럼 투명도가 필요 없는 이미지는 예외를 명시한다.

게임 컴포넌트는 개별 PNG의 원본 제작 방식이나 해시를 알지 않는다. 논리 ID로 계약을 조회하고, 계약의 칸 좌표로 스프라이트를 자른다. 따라서 새 이미지가 같은 계약을 만족하면 컴포넌트 코드는 바뀌지 않는다.

## 실패 처리

자산 파일이 없거나 디코딩에 실패하면 로딩 오류를 개발 로그에 남기되 게임은 계속 실행한다.

- 캐릭터·몬스터·보스: 크기와 진영 색이 구분되는 단순 도형
- 투사체·범위·피격 효과: 기존 절차적 도형
- 스테이지: 어두운 저대비 타일 패턴
- UI 아이콘: 텍스트 라벨 또는 기본 도형

대체 표시는 출시용 미술이 아니며 `temporary` 상태로만 허용한다. 릴리스 검증은 `approved`가 필요한 출시 범위에 임시 자산이 남아 있는지 별도로 보고한다.

## 귀여운 최종 아트 방향

최종 이미지 제작 단계에서는 다음 기준을 모든 캐릭터와 몬스터에 공통 적용한다.

- 큰 머리와 짧은 팔다리의 2~2.5등신 실루엣
- 둥글고 읽기 쉬운 외곽선과 과장된 표정
- 공포 요소는 잔혹함보다 장난스럽고 익살스러운 민속 괴물 표현
- 작은 모바일 화면에서도 진영과 공격 상태가 즉시 구분되는 색 대비
- 피, 신체 훼손, 사실적인 공포 묘사 제외
- 최종 반영 전 캐릭터·몬스터별 시안 검토와 사용자 승인 필수

## 데이터 흐름

1. 임시 또는 최종 PNG를 계약에 지정된 런타임 경로에 둔다.
2. 자동 검증이 크기, 색상 형식, 투명도, 프레임 수를 확인한다.
3. 게임이 논리 ID로 계약과 이미지를 불러온다.
4. 로딩 성공 시 아틀라스 프레임을 사용하고, 실패 시 안전한 대체 표시를 사용한다.
5. 최종 승인된 이미지만 상태와 권리 장부를 `approved`로 갱신한다.

## 테스트와 완료 기준

- 모든 등록 아틀라스의 파일 존재 여부와 정확한 전체 크기를 검사한다.
- 투명도가 필요한 PNG가 RGBA 형식인지 검사한다.
- 잘못된 행·열·프레임 인덱스를 계약 단계에서 거부한다.
- 자산 로딩 실패를 주입해 게임이 시작되고 전투 루프가 진행되는지 검사한다.
- 기존 전체 테스트, 웹 빌드, Android 디버그 빌드를 통과한다.
- 마스터 TODO에서 `VIS-008`~`VIS-010` 최종 이미지 작업은 사용자 승인 대기로 유지하고, `VIS-011`과 `VIS-012` 기반 검증 작업만 완료 처리한다.

## 기존 스테이지 아트 초안 처리

`codex/stage-art` 작업공간에 남아 있는 스테이지 이미지와 코드는 승인되지 않은 초안으로 보존한다. 현재 브랜치에는 병합하지 않으며, 향후 귀여운 최종 아트 방향이 확정되면 참고 또는 폐기 여부를 결정한다.
