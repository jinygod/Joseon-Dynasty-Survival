# 가로형 출시 품질 로비 디자인

작성일: 2026-07-25

## 1. 목표

현재 로비를 기능 검증용 화면이 아니라 실제 출시 게임의 첫 화면으로 재구성한다.
사용자가 제시한 참고 이미지에서 다음 품질 기준을 가져오되, 프로젝트의 가로형
모바일 화면과 기존 조선 민속 판타지 아트 방향에 맞게 다시 설계한다.

- 궁궐 배경과 캐릭터가 하나의 중심 장면으로 읽힌다.
- 화면을 처음 본 사용자가 출진, 성장, 수집 메뉴의 우선순위를 바로 이해한다.
- 메뉴 프레임, 재화, 아이콘, 버튼이 같은 재질과 외곽선 규칙을 사용한다.
- 구현되지 않은 메뉴도 눌렀을 때 자연스러운 세계관 안내를 제공한다.
- 기본 Material `Card`, `ListTile`, `AppBar`, `ActionChip`을 최종 로비 표현으로
  사용하지 않는다.
- 임시 도형이나 “추후 교체” 상태를 출시 로비 완료로 간주하지 않는다.

## 2. 범위

이번 작업에 포함한다.

- 로비 전체 레이아웃 재구성
- 로비 배경과 캐릭터 프레젠테이션 개선
- 상단 프로필 및 재화 표시
- 좌우 보조 메뉴
- 중앙 출진 정보와 주요 행동 버튼
- 하단 빠른 메뉴 및 주 내비게이션
- 메뉴별 미구현 안내 패널
- 로비용 실제 PNG 프레임, 아이콘, 초상화 제작과 적용
- 가로형 모바일 화면비 대응
- 로비 위젯 테스트, 실행 화면 캡처 및 시각 검토

이번 작업에서 제외한다.

- 미구현 메뉴의 실제 게임 시스템
- 신규 재화, 캐릭터, 무기, 스테이지 콘텐츠
- 전투 밸런스 변경
- 세로형을 기본 플레이 방향으로 만드는 변경
- 배경과 모든 UI 문구를 한 장의 이미지에 굽는 방식

## 3. 현재 구조와 문제

현재 `LobbyScreen`은 전체 배경 위에 상단 명령 바, 중앙 `LobbyBattleStage`,
하단 `LobbyNavigationDock`을 배치한다. 중앙 무대는 같은 궁궐 이미지를 한 번 더
카드 안에 표시하며, 금색 테두리와 둥근 사각형으로 장면을 분리한다.

현재 구조의 주요 문제는 다음과 같다.

- 전체 배경과 중앙 카드 배경이 중복되어 하나의 장면으로 이어지지 않는다.
- 상단 재화와 하단 메뉴가 Material 아이콘 및 코드 도형 중심이다.
- 설정과 상점 진입에 기본 Material 표현이 남아 있다.
- `AssetCatalog.characterPortraits`의 초상화 3종이 실제 파일 없이 선언되어 있다.
- 중앙 출진 영역이 참고 이미지보다 작고, 캐릭터가 장면의 주인공으로 보이지 않는다.
- 기존 세로형 배경을 가로 화면에서 단순 `cover`로 잘라 주요 랜드마크와 캐릭터가
  동시에 안정적으로 보이지 않는다.

## 4. 선택한 접근

장면형 로비와 모듈식 PNG UI를 결합한다.

배경, 캐릭터, 조명은 하나의 본진 장면처럼 구성한다. 프로필, 재화, 메뉴, 출진
버튼은 독립된 PNG 프레임과 Flutter 텍스트로 구성한다. 이 방식은 전체 로비를
한 장의 이미지로 만드는 방식보다 화면비 대응과 기능 변경이 쉽고, 현재 코드에
장식만 추가하는 방식보다 게임다운 깊이와 정보 위계가 분명하다.

## 5. 화면 구성

### 5.1 기준 화면

- 기본 방향: 가로
- 기준 비율: 16:9
- 추가 검증: 19.5:9 및 20:9 가로
- 최소 논리 높이: 360
- SafeArea를 제외한 가용 영역에 맞춰 비율 기반으로 배치한다.
- 세로 화면에서는 회전 안내 또는 제한된 축약 로비를 보여주되, 세로형을 기본
  레이아웃으로 재설계하지 않는다.

### 5.2 레이어 순서

뒤에서 앞으로 다음 순서를 사용한다.

1. 밤 궁궐 배경
2. 가장자리 비네트와 국소 조명
3. 중앙 캐릭터와 캐릭터 그림자
4. 스테이지 정보 및 출진 명판
5. 상단 프로필과 재화
6. 좌우 보조 메뉴
7. 하단 빠른 메뉴와 주 내비게이션
8. 미구현 기능 안내 패널

### 5.3 가로 배치

- 상단 좌측: 프로필 초상화, 게임명, 수련 단계
- 상단 중앙·우측: 엽전, 혼옥, 유료 재화, 설정
- 좌측 세로 메뉴: 상점, 임무, 승급 패스, 패키지
- 우측 세로 메뉴: 우편, 설정, 도감, 기록
- 중앙: 선택 캐릭터, 캐릭터명, 현재 스테이지, 최고 기록
- 중앙 하단: 가장 큰 `출진` 버튼
- 출진 버튼 주변: 장비와 유물 등 현재 실제 기능으로 연결되는 빠른 행동
- 최하단: 로비, 인물, 전투, 도전, 상점의 주 내비게이션

작은 가로 화면에서는 좌우 메뉴를 한 줄짜리 축약 아이콘 레일로 줄이고, 중앙
캐릭터와 출진 버튼의 크기는 우선 보존한다.

## 6. 시각 시스템

### 6.1 재질

- 기본 프레임: 검은 옻칠 목재
- 외곽선: 오래된 황동과 아이보리 이중선
- 주요 버튼: 따뜻한 한지와 황금 금속 모서리
- 위험 및 전투 강조: 절제된 주홍색
- 성장 및 자연 계열: 짙은 옥색
- 비활성 상태: 회갈색 목재와 낮은 채도

### 6.2 형태

- 프레임 모서리는 조선 창호와 단청 문양을 단순화한 장식으로 통일한다.
- 버튼의 누름 상태는 2~4픽셀 깊이 이동, 밝기 감소, 짧은 광택 변화로 표현한다.
- 원형 또는 둥근 사각형만으로 메뉴를 완성하지 않는다.
- 문양은 모서리와 구분선에 제한하고 텍스트 주변을 복잡하게 만들지 않는다.

### 6.3 글자

- 제목: `SongMyung`
- 본문과 숫자: `GowunBatang`
- 텍스트는 PNG에 포함하지 않고 Flutter에서 렌더링한다.
- 숫자는 작은 화면에서도 한눈에 읽히도록 그림자 또는 얇은 어두운 외곽선을 쓴다.

## 8. 기능 연결

현재 구현된 기능은 기존 데이터와 내비게이션을 유지한다.

| 메뉴 | 동작 |
|---|---|
| 출진 | 현재 선택 캐릭터와 스테이지로 전투 시작 |
| 지도 | 스테이지 선택 화면 |
| 인물 | 캐릭터 선택 화면 |
| 도감 | 도감 화면 |
| 기록 | 기록 화면 |
| 수련 또는 성장 | 수련 화면 |
| 설정 | 설정 화면 |
| 상점 | 현재 구매 시스템 상태에 따라 상점 또는 재시도 안내 |

현재 구현되지 않은 기능은 공통 `FeatureNoticePanel`을 열며, 메뉴별 문구를
사용한다.

| 메뉴 | 제목 | 안내 문구 |
|---|---|---|
| 우편 | 전령의 소식 | 전령이 새로운 소식을 모으고 있습니다. |
| 임무 | 임무서 | 관아에서 오늘의 임무서를 정리하고 있습니다. |
| 승급 패스 | 승급 준비 | 새 승급 보상이 도착할 때까지 잠시 기다려 주십시오. |
| 패키지 | 보급품 | 상단이 새로운 보급품을 들여오고 있습니다. |
| 랭킹 | 무예 명부 | 전국의 무예 기록을 한데 모으고 있습니다. |
| 유물 | 봉인된 유물 | 감정이 끝난 유물부터 차례로 공개됩니다. |
| 동료 | 인연 | 함께 싸울 인연을 찾고 있습니다. |
| 제작 | 대장간 | 대장간의 화로를 달구고 있습니다. |
| 도전 | 봉인된 시련 | 봉인된 시련의 문이 아직 열리지 않았습니다. |

안내 패널은 단순 `SnackBar`가 아니라 로비 시각 시스템을 따르는 작은 한지·목재
오버레이로 표시한다. 확인 버튼과 바깥 영역 탭으로 닫을 수 있다.

## 9. 컴포넌트 경계

- `LobbyScreen`: 데이터와 내비게이션 콜백 조립
- `LobbyScene`: 배경, 캐릭터, 장면 조명
- `LobbyStatusBar`: 프로필과 재화
- `LobbySideMenu`: 좌우 보조 메뉴
- `LobbyDeploymentPanel`: 스테이지 정보와 출진
- `LobbyQuickActions`: 성장·무기·유물·동료·제작
- `LobbyPrimaryNavigation`: 로비·인물·전투·도전·상점
- `FeatureNoticePanel`: 메뉴별 미구현 안내
- `LobbyAssetCatalog`: 로비 전용 PNG 경로와 상태별 에셋

각 컴포넌트는 내비게이션을 직접 소유하지 않고 콜백을 받는다. 저장 상태와 전투
진입 로직은 기존 `LobbyController` 및 현재 화면 전환 코드를 유지한다.

## 10. 오류와 누락 대응

- 프로젝트에 포함되는 모든 새 에셋은 테스트에서 실제 파일 존재 여부를 확인한다.
- 로비 핵심 에셋 로딩 실패는 Material 아이콘으로 대체하지 않는다.
- 개발 빌드에서는 실패한 에셋 경로를 명확히 표시한다.
- 출시 빌드에서는 검증된 공통 로비 폴백 프레임과 기본 캐릭터 전신을 사용한다.
- 상점 초기화 실패는 아무 반응 없이 끝내지 않고 로비 스타일 안내 패널로 재시도
  상태를 전달한다.

## 11. 접근성과 입력

- 모든 메뉴는 최소 48×48 논리 픽셀 입력 영역을 확보한다.
- 아이콘에는 한국어 의미 라벨을 제공한다.
- 색상만으로 선택과 비활성 상태를 구분하지 않는다.
- 시스템 글자 확대 시 중요한 숫자와 출진 버튼이 잘리지 않는다.
- 화면 읽기 순서는 프로필, 재화, 중앙 출진, 보조 메뉴, 하단 내비게이션 순으로
  유지한다.

## 12. 검증

### 12.1 자동 검증

- 로비 주요 메뉴가 올바른 콜백을 호출한다.
- 미구현 메뉴가 해당 문구의 `FeatureNoticePanel`을 연다.
- 16:9, 19.5:9, 20:9 가로 크기에서 overflow가 발생하지 않는다.
- 캐릭터 및 로비 에셋 경로가 모두 존재한다.
- 로비에 기본 Material `Card`, `ListTile`, `AppBar`, `ActionChip`이 남지 않는다.
- 출진 중 중복 탭이 기존과 같이 차단된다.

### 12.2 실행 화면 검증

- 중앙 캐릭터가 배경과 UI보다 먼저 눈에 들어온다.
- 출진 버튼이 가장 강한 행동 우선순위를 가진다.
- 좌우 메뉴가 전투 장면과 캐릭터를 가리지 않는다.
- 작은 화면에서 아이콘과 숫자를 확대하지 않고도 읽을 수 있다.
- 배경, 캐릭터, 버튼, 아이콘의 외곽선과 광원 방향이 일치한다.
- 미구현 메뉴 안내가 임시 개발 팝업처럼 보이지 않는다.
- 웹과 Android 실제 실행 화면을 캡처해 참고 이미지와 정보 밀도, 깊이감,
  가독성을 비교한다.

## 13. 완료 조건

다음 조건을 모두 만족할 때 로비 개편을 완료로 처리한다.

- 새 로비용 PNG가 실제 코드에 연결되어 있다.
- 누락된 캐릭터 초상화와 중앙 전신 에셋이 존재한다.
- 기본 Material 기반 최종 로비 요소가 제거되어 있다.
- 구현 및 미구현 메뉴가 모두 자연스럽게 반응한다.
- 가로형 모바일 화면에서 잘림과 overflow가 없다.
- 실제 실행 화면을 검토하고 가독성 또는 재질 통일이 부족한 에셋을 한 차례 이상
  재검토했다.
- 관련 테스트, `flutter analyze`, 전체 `flutter test`, `flutter build web`,
  Android 빌드가 성공한다.
- 최종 변경 사항과 실행 화면이 GitHub 원격 저장소에 반영된다.
