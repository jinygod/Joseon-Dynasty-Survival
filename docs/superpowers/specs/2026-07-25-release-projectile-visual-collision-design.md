# 릴리스 투사체 시각·연속 충돌 설계

- 날짜: 2026-07-25
- 기준 커밋: `b0dc78c`
- 제품 방향: 출시 가능한 가로형 모바일 조선 민속 판타지 뱀서라이크

## 문제 확인

코드에는 `brick` 또는 벽돌 무기 ID가 없다. 사용자가 벽돌처럼 본 표현은
`ProjectileComponent`의 공용 표현 경로에서 나온다.

- 신기전 PNG의 각 128px 프레임에는 불필요한 사각 테두리가 들어 있어
  축소 렌더링 시 투사체가 네모난 벽돌처럼 보인다.
- 조총·화포와 수호매는 전용 투사체 PNG가 없어 단색 타원 fallback으로
  표시된다.
- 각궁은 28px 화살을 표시하지만 충돌 크기는 별도의 8px 정사각형 값에서
  원형으로 계산된다.
- 모든 플레이어 투사체는 이전 위치를 무시하고 현재 중심점 사이의 거리만
  비교하므로 빠른 이동에서 적을 통과할 수 있다.
- 적 충돌에는 승인된 `EnemyComponent.hurtRadius` 대신 전체 `enemy.size.x / 2`
  상당의 범위가 사용된다.

새 벽돌 무기는 만들지 않는다. 이번 패스는 벽돌처럼 보이는 공용 투사체
경로를 실제 무기별 표현과 연속 충돌 계약으로 교체한다.

## 선택한 접근

모든 이동형 플레이어 투사체가 공유하는 `ProjectilePresentationSpec`을
도입한다. 이 사양은 에셋, 프레임, 화면상 본체 크기, 진행 방향, 판정 inset을
함께 소유한다. 렌더링과 충돌은 이 사양에서 각각 값을 가져오며 독립적인
임의 반경을 갖지 않는다.

이번 패스에서 다루는 무기는 다음 네 가지다.

1. 각궁: 기존 화살 아트 유지, 방향성 판정으로 이관
2. 신기전: 사각 테두리 없는 새 4프레임 PNG로 교체
3. 조총·화포: 불꽃과 연기를 동반한 철환 전용 PNG 추가
4. 수호매: 작은 매 실루엣의 비행 4프레임 PNG 추가

피해량, 공격 속도, 이동 속도, 관통 수, 발사 수, cooldown과 무기 레벨
수치는 변경하지 않는다.

## 데이터 소유권

`ProjectilePresentationSpec`은 다음 값을 가진다.

- `weaponId`
- `assetKey`
- `frameSize`
- `frameCount`
- `frameSeconds`
- `renderSize`
- `bodySize`
- `hitInsetFraction`
- `rotateWithVelocity`
- `assetForwardAngle`
- `filterQuality`

`renderSize`는 투명 여백을 포함한 화면 표시 셀이고 `bodySize`는 그 안에서
실제로 보이는 투사체 본체의 길이와 두께다. 판정 크기는 항상
`bodySize * (1 - hitInsetFraction)`로 계산한다. 기본 inset은 10%이며
허용 범위는 5~15%다.

`ProjectileComponent` 생성자는 무기별 임의 충돌 `size`를 받지 않는다.
증강의 크기 배율만 별도로 받아 사양의 `renderSize`, `bodySize`, 판정에
동일하게 적용한다.

## 렌더링 계약

- 모든 투사체는 투명 배경 PNG를 사용한다.
- 런타임에서 단색 원·타원·사각형 fallback을 그리지 않는다.
- 이미지 로드는 전투 시작 전에 완료하며 발사 중 새 이미지 로드를 시작하지
  않는다.
- 에셋이 누락되거나 프레임 계약이 틀리면 에셋 계약 테스트와 개발 로딩을
  실패시킨다.
- 디버그 빌드의 visual bounds와 hitbox 선은 개발 표시이며 최종 표현으로
  사용하지 않는다.

### 아트 방향

- 공통: 먹빛 외곽선, 아이보리 하이라이트, 제한된 금색 강조, 배경보다 높은
  명도 대비, 오른쪽을 기본 진행 방향으로 제작
- 신기전: 목재 화살대와 붉은 화약통, 짧은 금빛 점화 불꽃, 프레임 테두리와
  카드형 배경 금지
- 조총·화포: 불규칙한 철환 실루엣, 주홍 화염핵, 짧은 회색 연기 꼬리,
  단순 원형 아이콘처럼 보이는 외곽 금지
- 수호매: 펼친 날개와 갈고리 부리의 명확한 실루엣, 남청색 깃털과 금갈색
  날개 끝, 새가 아닌 탄환처럼 보이는 과도한 광원 금지

생성 원본은 `art_source/generated/projectiles/`, 채택 결과는
`assets/images/projectiles/player/`에 저장한다.

## 연속 충돌 계약

1. 프레임 갱신 시작 시 투사체의 `previousPosition`을 보관한다.
2. 현재 속도와 `dt`로 `position`을 이동한다.
3. 충돌 단계는 이전 중심에서 현재 중심까지의 선분에 판정 반두께를 더한
   swept capsule을 만든다.
4. 캡슐의 시작과 끝은 투사체 진행 방향으로 판정 반길이만큼 확장한다.
5. 적은 `EnemyComponent.hurtRadius` 원으로 검사한다.
6. 캡슐과 hurtbox가 처음 만나는 sweep 진행률을 계산한다.
7. 같은 프레임에 여러 적이 교차하면 진행률이 빠른 순서로 처리한다.
8. 관통 수가 소진되면 이후 교차 대상은 처리하지 않는다.

정지하거나 이동량이 극히 작은 투사체는 현재 위치의 방향성 캡슐과
hurtbox를 검사한다. 빠른 투사체를 위해 매 프레임 path 객체나 Flame
collision component를 새로 생성하지 않고 벡터·스칼라 계산만 사용한다.

## 접촉 데이터와 피드백

충돌 함수는 단순한 `bool` 대신 다음 정보를 가진
`ProjectileContact`를 반환한다.

- 대상
- sweep 진행률
- 월드 접촉점
- 접촉 법선
- 투사체 진행 방향

피해, 넉백 방향, 피격 VFX 위치가 같은 contact를 소비한다. 접촉점은 적
중심이 아니라 swept capsule과 적 hurtbox가 처음 만난 월드 위치다.
기존 피격 플래시와 넉백은 유지하고, 투사체용 접촉 VFX는 실제 접촉점에
표시한다. 동일 투사체와 동일 적 조합은 한 번만 피해를 적용한다.

## 디버그 표시

개발 모드에서 기존 전투 판정 디버그 토글에 다음을 추가한다.

- 투사체 visual body bounds
- 현재 방향성 hit capsule
- 이전 위치에서 현재 위치까지의 swept capsule
- 적 hurtbox
- 최초 contact point와 normal
- 무기 ID

릴리스 빌드에서는 이 구성 요소와 텍스트를 생성하지 않는다.

## 일시정지와 제거 처리

- pause, level-up overlay, 사망으로 전투 갱신이 정지하면 이전 위치와 현재
  위치도 함께 정지한다.
- 재개 첫 프레임에 정지 전 이동 구간을 다시 sweep하지 않는다.
- 수명 종료, 월드 이탈, 관통 소진 후에는 새 contact를 만들지 않는다.
- 에셋 로드 실패가 피해 중복이나 보이지 않는 투사체 공격으로 이어지지
  않게 전투 시작을 실패시킨다.

## 테스트

- 신기전 채택 PNG의 네 모서리와 셀 경계가 투명
- 조총·화포와 수호매가 단색 fallback 없이 전용 PNG 사용
- 모든 투사체 사양의 판정이 visual body보다 정확히 10% 작음
- 렌더 회전과 hit capsule 진행 방향이 동일
- 한 프레임에 적을 통과해도 swept collision으로 적중
- swept capsule 밖의 가까운 적은 미적중
- 적의 `hurtRadius` 밖에서는 미적중
- 다중 적 교차 시 거리순 처리와 관통 수 보존
- 동일 대상 중복 피해 없음
- contact point가 visual sweep과 적 hurtbox 양쪽 경계에 일치
- pause와 level-up 재개 후 과거 구간 중복 적중 없음
- 기존 레벨 1~6 피해량, 발사 수, 속도, 관통 수, cooldown 보존
- 릴리스 트리에 도형 fallback 렌더 경로가 없음

## 실행 검증

1. 투사체 gallery에서 네 무기를 8방향, 0.25배·1배 속도로 검토
2. 밝은 바닥과 어두운 바닥에서 1배·축소 모바일 크기 가독성 확인
3. Chrome landscape에서 단일 적과 일렬로 배치한 다중 적에 발사
4. visual bounds, swept capsule, hurtbox, contact point를 함께 캡처
5. 16:9와 19.5:9 전투 화면에서 사각 테두리·도형 fallback 부재 확인
6. 가독성 또는 접촉 위치가 부족하면 PNG나 body bounds 한 원인만 조정
7. 관련 테스트와 `flutter analyze`
8. 전체 `flutter test`
9. Android debug APK 빌드

## 완료 조건

- 신기전의 벽돌 같은 사각 테두리가 보이지 않는다.
- 조총·화포와 수호매가 무기 정체성을 가진 실제 PNG로 보인다.
- 모든 이동 투사체가 보이는 본체와 같은 방향·크기 데이터로 판정된다.
- 빠른 투사체가 적을 통과하지 않고 실제 최초 접촉점에서만 피해를 준다.
- 화면상 이미지와 닿지 않은 적에게 피해가 발생하지 않는다.
- 실제 landscape 실행 캡처에서 투사체가 배경·적과 구분된다.
- 관련 테스트, analyze, 전체 테스트, Android APK 빌드 결과가 보고서에
  기록된다.
