# 전투 리듬 로그 기준

`BAL-001` 이후의 모든 밸런스 시뮬레이션은 같은 구간과 스냅샷 형식을 사용한다. 한 런의 기본 전투 시간은 300초이며, 270초에 등장한 보스를 검증할 수 있도록 최대 330초까지 기록한다.

## 구간 정의

| 구간 ID | 시간 | 플레이어 경험 목표 | 우선 확인 지표 |
| --- | ---: | --- | --- |
| `learning` | 0:00–0:59 | 이동·자동 공격 이해, 첫 레벨업 경험 | 첫 레벨업 시점, 받은 피해, 적 동시 수 |
| `build` | 1:00–2:59 | 무기·증강 선택으로 빌드 방향 형성 | 레벨업 횟수, 무기별 피해, 처치 속도 |
| `pressure` | 3:00–4:29 | 완성된 빌드로 밀도·엘리트 압박 대응 | 체력 손실, 활성 적 수, 엘리트 생성 수 |
| `boss` | 4:30–5:30 | 잔여 적 관리와 보스 패턴 대응 | 보스 체력 변화, 보스전 피해, 사망 시점 |

경계 시각은 뒤 구간에 포함한다. 예를 들어 60초는 `build`, 180초는 `pressure`, 270초는 `boss`다.

## 수집 규칙

- 고정 시드 시뮬레이션은 0초부터 330초까지 15초마다 한 행을 기록한다.
- 누적 값은 런 시작부터 현재 스냅샷까지의 값이다. `spawnedEnemies`, `eliteSpawns`, 피해량과 처치 수도 누적으로 유지한다.
- `weaponDamageTotals`의 키는 표시명이 아닌 안정적인 콘텐츠 ID를 사용한다.
- 보스가 아직 없으면 `bossHealthFraction`은 `null`, 등장 후에는 0~1 비율을 기록한다.
- 모든 비율은 0~1, 모든 카운터와 피해량은 0 이상이어야 한다. 잘못된 표본은 비교 데이터에 포함하지 않는다.

## JSON 필드

필수 필드는 `second`, `phase`, `activeEnemies`, `spawnedEnemies`, `eliteSpawns`, `playerLevel`, `healthFraction`, `kills`, `damageDealt`, `damageTaken`, `weaponDamageTotals`, `bossHealthFraction`이다. 코드 기준은 `CombatRhythmSnapshot.toJson()`이다.

## 후속 판정 방식

- `BAL-002`: 15초 구간별 무기 피해 증가량으로 DPS와 특정 무기 독점 여부를 계산한다.
- `BAL-003`: 레벨 변화 시각과 최종 레벨로 평균 레벨업 8~12회 목표를 검증한다.
- `BAL-004`~`BAL-006`: 활성 적, 체력 손실, 엘리트 수, 보스 체력 기울기로 난이도 급등과 억울한 피격 후보를 찾는다.
- `BAL-008`: 여러 고정 시드가 동일한 로그 스키마와 구간 경계를 유지하는지 회귀 검증한다.

이 로그는 자동 밸런스 판정의 입력이다. 최종 재미·재도전 의사·억울한 피격 판단은 실제 플레이테스트 지표와 함께 결정한다.
