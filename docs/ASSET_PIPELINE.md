# 릴리스 에셋 파이프라인

## 목적

게임에서 소비되는 모든 래스터 에셋을 생성, 검수, 후처리, 등록, 실행 검증까지 추적한다. “나중에 교체”하는 임시 에셋은 릴리스 후보에 포함하지 않는다.

## 디렉터리 계약

- `art_source/generated/`: 생성 원본과 채택 전 후보. 런타임 manifest에 등록하지 않는다.
- `art_source/review/`: 실제 크기 비교 시트와 검토 캡처.
- `assets/images/player/`: 플레이어 전투 시트.
- `assets/images/enemies/`, `assets/images/monsters/`: 적·보스 전투 시트.
- `assets/images/weapons/`: 무기 본체와 투사체.
- `assets/images/vfx/`: 공격 궤적, 피격, 상태 효과.
- `assets/images/ui/`: 버튼, 패널, 탭, 배지, 화면 장식.
- `assets/images/characters/`: 로비·도감용 캐릭터 일러스트.
- `assets/images/stages/`: 로비·스테이지 카드 일러스트.
- `docs/assets/`: 프롬프트, 권리 장부, 검수 결과.

## 파일 이름

`<대상>_<동작 또는 용도>_<셀크기>[_v번호].png`를 사용한다.

예:

- `hwando_slash_trail_128.png`
- `hwando_contact_spark_128.png`
- `matchlock_projectile_64.png`
- `codex_weapon_frame_512_v2.png`

기존 파일을 교체할 때도 검토 전에는 버전 이름으로 저장한다. 채택 후 참조를 새 파일로 바꾸며 원본을 무단 덮어쓰지 않는다.

## 생성 규칙

1. 해당 에셋의 실제 표시 크기, 카메라 줌, 배경 샘플을 먼저 확인한다.
2. 프롬프트에 조선 민속 판타지, 형태 덩어리, 광원, 외곽선, 사용 위치, 금지 요소를 명시한다.
3. 불투명한 단일 오브젝트는 평평한 크로마키 배경으로 생성한다.
4. 연기, 머리카락, 반투명 광원처럼 크로마키가 부적합한 경우 임의로 모델을 바꾸지 않고 별도 투명 출력 경로 승인을 받는다.
5. 한 번의 결과를 자동 채택하지 않는다. 최소한 실제 화면 합성 또는 런타임 캡처로 비교한다.

## 투명 PNG 후처리

- 기본 키 색은 피사체에 없는 `#00FF00` 또는 `#FF00FF`를 사용한다.
- 배경은 그림자, 그라데이션, 바닥면 없이 완전한 단색이어야 한다.
- 키 제거 후 RGBA 채널, 네 모서리 알파 0, 색 번짐, 잘린 외곽선을 검사한다.
- 필요하면 1px edge contract를 한 번 적용하고, 얇은 무기나 반사면이 손상되면 원본 생성부터 다시 한다.
- 스프라이트의 유효 픽셀 경계와 pivot을 기록한다.

## 스프라이트 시트

- 전투 시트의 모든 프레임은 동일한 셀 크기와 기준점을 사용한다.
- 발 위치 또는 무기 손잡이 같은 anchor가 프레임 사이에서 흔들리지 않아야 한다.
- 빈 프레임, 잘린 픽셀, 셀 침범, 비정상 투명 여백을 자동 검사한다.
- 프레임별 visual bounds를 계산하고 런타임 hitbox 산출의 입력으로 저장한다.
- 애니메이션 행과 프레임 의미는 코드 레지스트리와 문서에 동시에 기록한다.

## 등록 절차

1. 최종 PNG를 `assets/images/` 하위의 목적별 디렉터리에 복사한다.
2. `pubspec.yaml`의 포함 범위를 확인한다.
3. `AssetCatalog` 또는 전투 전용 레지스트리에 고유 키로 등록한다.
4. 임시 atlas 전체를 여러 도감 항목의 대표 이미지로 재사용하지 않는다.
5. 에셋 누락 시 릴리스 빌드가 generic 도형으로 계속 진행하지 않도록 계약 테스트를 둔다.
6. `docs/assets/asset-rights-ledger.csv`에 출처와 권리를 기록한다.

## 검수 단계

### 파일 검수

- PNG 시그니처와 RGBA
- 예상 크기와 프레임 수
- 투명 모서리와 유효 픽셀 비율
- SHA-256
- 다른 콘텐츠와의 중복 여부

### 갤러리 검수

- 밝은 배경과 어두운 배경
- 0.75배, 1배, 1.25배
- 좌우 및 8방향 회전
- 첫 프레임, 중간 프레임, 마지막 프레임
- visual bounds, anchor, pivot 오버레이

### 실행 검수

- 실제 가로형 모바일 viewport
- 실제 카메라 줌과 배경
- 적 1기, 밀집 적, HUD와 겹치는 상황
- 저성능 모드가 아닌 기본 품질
- 전투 중 이미지 로딩이 없는지 확인

## 반복 기준

다음 중 하나라도 발생하면 채택하지 않고 한 가지 원인만 수정해 재생성 또는 후처리한다.

- 24~40px 표시에서 형태가 뭉개짐
- 배경과 명도 차이가 부족함
- 외곽선 굵기나 광원 방향이 다른 에셋과 다름
- 공격 방향이 읽히지 않음
- 투명 여백 때문에 visual bounds가 판정과 어긋남
- 모바일 캡처에서 효과가 적이나 플레이어를 과도하게 가림

## 산출 기록

각 채택 에셋은 다음 정보를 남긴다.

- 최종 경로
- 사용 화면 또는 전투 ID
- 생성 도구와 최종 프롬프트
- 입력 참조 이미지와 역할
- 후처리 명령
- 원본 및 최종 SHA-256
- 검토한 캡처 경로
- 채택 또는 폐기 사유

## 릴리스 차단 조건

- `Temporary`, `placeholder`, `ASSET MISSING` 상태
- 캐릭터·몬스터·무기·효과의 Canvas 도형 fallback
- 도감 항목 여러 개가 같은 atlas 전체를 썸네일로 사용
- 런타임 첫 사용 시 이미지 로드
- visual bounds와 hitbox가 서로 다른 독립 상수에서 계산됨
