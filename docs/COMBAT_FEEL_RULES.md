# 전투 감각과 판정 규칙

## 단일 진실 공급원

모든 공격은 하나의 불변 `AttackPresentationContract`에서 타임라인, 시각 범위, 판정 범위, 방향, anchor를 파생한다. 렌더러와 피해 판정이 서로 다른 반경·각도·길이 상수를 소유하지 않는다.

계약의 필수 데이터:

- 공격 ID와 공격 주체
- 월드 원점과 고정된 단위 방향
- 준비, 활성 타격, 회복 시간
- 시각 도형의 길이, 각도, 폭 또는 반경
- hitbox inset 비율
- 프레임별 활성 구간
- 스프라이트 asset key, pivot, scale
- 피해, 넉백, hit stop, 피격 플래시, 사운드 cue

## 시각 범위와 hitbox

- 기본 hitbox는 시각 유효 범위보다 10% 작게 한다.
- 허용 범위는 5~15%이며 무기별 예외는 계약에 명시한다.
- 투명 여백은 시각 범위로 계산하지 않는다.
- 적 hurtbox는 `size.x / 2` 같은 표시 사각형의 임의 반경이 아니라 실제 몸통 bounds로 정의한다.
- 판정은 공격 이미지의 밝은 잔광 전체가 아니라 무기 본체와 핵심 에너지 띠를 기준으로 한다.

## 공격 타임라인

1. 준비: 방향을 고정하고 예비 동작만 표시한다. 피해 판정은 비활성이다.
2. 타격: 실제 무기 또는 검기가 목표 영역을 지나는 프레임에서만 판정을 활성화한다.
3. 접촉: 최초 충돌 위치를 계산하고 피해, 넉백, 피격 효과, 사운드를 한 번 적용한다.
4. 회복: 잔광은 남을 수 있지만 새 피해 판정은 비활성이다.

한 공격이 여러 대상을 맞힐 수 있어도 동일 대상에 대한 중복 타격 규칙은 공격 계약에 명시한다.

## 환도베기 기준

- 기본 베기는 준비 0.06초, 활성 0.08초, 회복 0.10초를 초기값으로 사용한다.
- 부채꼴 중심 방향과 PNG 회전은 같은 고정 방향 벡터를 사용한다.
- visual sector는 무기 레벨의 범위와 각도를 사용하고 hit sector는 반경과 각도를 각각 10% 줄인다.
- 판정은 활성 구간에만 평가한다.
- 접촉점은 적 hurtbox 원과 부채꼴 경계 또는 검날 중심선의 가장 가까운 점으로 계산한다.
- 피격 베기와 불꽃은 접촉점에서 0.12~0.18초 재생한다.
- 좌우 연속 베기는 각각 별도의 타임라인과 이미 맞은 대상 집합을 가진다.

## 빠른 투사체

- 매 프레임 이전 위치를 보관한다.
- 이전 위치와 현재 위치 사이의 선분에 투사체의 실제 몸체 반경을 더한 swept capsule로 적 hurtbox와 검사한다.
- 접촉 시간 `t`가 가장 작은 충돌부터 처리해 관통 순서를 보존한다.
- 판정 반경은 표시 이미지 유효 폭의 85~95%를 사용한다.
- 잔상은 판정에 포함하지 않는다.
- 투사체가 한 프레임에 적을 통과해도 접촉을 놓치지 않는다.

## 피격 반응

- hit stop: 일반 20~35ms, 강공격 40~60ms, 보스 타격은 최대 70ms
- 피격 플래시: 45~80ms, 완전 흰색 유지가 아니라 원본 색을 일부 보존
- 넉백: 충돌 지점에서 적 중심으로 향하는 방향
- 피격 VFX: 실제 contact point, 공격 속성과 일치하는 색
- 사운드: 짧은 시간 창에서 중첩 제한, 연속 타격은 제한된 pitch variation
- 화면 흔들림: 강공격과 보스 타격에만 사용하고 UI에는 적용하지 않음

피해 숫자와 피격 VFX가 먼저 보이고 실제 체력 감소가 나중에 일어나는 순서 역전을 허용하지 않는다.

## 접촉 피해

- 플레이어와 몬스터의 hurtbox가 실제 몸체 이미지 범위에서 겹칠 때만 발생한다.
- 표시 크기 전체를 반경으로 사용하지 않는다.
- 장식, 그림자, 무기 끝, 투명 여백은 몸통 hurtbox에 포함하지 않는다.
- 접촉 cooldown은 판정 오류를 숨기는 용도로 사용하지 않는다.

## 중단 상태

- 일시정지와 레벨업에서는 새 공격 판정과 타임라인 진행을 멈춘다.
- 이미 적용된 피해를 다시 적용하지 않는다.
- 사망 시 대기 중인 공격과 접촉 이벤트를 취소한다.
- 재개 시 이전 프레임 위치를 현재 위치로 재설정해 거대한 swept segment가 생기지 않게 한다.

## 디버그 표시

개발 빌드에서 다음을 독립적으로 켤 수 있어야 한다.

- visual bounds: 청록
- active hitbox: 주홍
- inactive 예정 hitbox: 반투명 금색
- player/enemy hurtbox: 아이보리
- swept segment/capsule: 청색
- contact point: 밝은 자홍 십자
- 공격 단계와 남은 시간

디버그 도형은 개발 전용이며 릴리스 렌더링 에셋을 대신하지 않는다.

## 검증

- 경계 안의 적은 맞고 1px 바깥의 적은 맞지 않는 단위 테스트
- 준비와 회복 중 피해가 발생하지 않는 타임라인 테스트
- 30, 60, 120fps에서 같은 대상과 접촉 순서를 얻는 테스트
- 빠른 투사체가 한 프레임에 hurtbox를 통과하는 swept collision 테스트
- 접촉점이 시각 효과 내부에 있는지 검사
- 동일 공격·동일 대상 중복 피해 방지
- 실제 실행에서 디버그 오버레이와 PNG를 함께 캡처해 육안 검토

## 완료 조건

테스트 통과만으로 완료하지 않는다. 실제 가로형 모바일 실행 화면에서 공격 이미지와 hitbox가 납득 가능하게 겹치고, 공격 준비·타격·회복과 접촉점 피격이 눈으로 확인되어야 한다.
